# NovaMath Lab — Badge Catalog

## Purpose

NovaMath Lab includes 100 collectible badges. They are designed to make growth visible without encouraging rushed answers, unhealthy streaks, or fear of mistakes.

The complete generated art set is stored in `assets/badges/`; see [BADGE_ART_DIRECTION.md](BADGE_ART_DIRECTION.md) for its themes, tier styling, and generation prompt set.

| Tier | Count | Expected horizon |
| --- | ---: | --- |
| Starter | 25 | First few sessions |
| Intermediate | 50 | Several weeks of varied practice |
| Advanced | 25 | Sustained mastery over months |
| **Total** | **100** | |

## Badge rules

- A badge is awarded once and keeps its original earned date.
- Progress is calculated from validated learning events, never from the interface alone.
- “Correct” means an answer accepted by the question engine. When specified, “without a hint” excludes any question for which a hint was opened.
- A “strong session” is a completed session with at least eight questions and at least 80% correct.
- A “perfect session” is a completed session with at least eight questions, every answer correct, and no hints.
- “Distinct days” do not need to be consecutive. Missing a day never removes progress.
- Mission badges use completed mission stages, not merely opening a mission.
- Imported progress must not award duplicates.

## Presentation and accessibility

- Each badge has a name, short description, tier, icon, current progress, and unlock date.
- Earned badges use tier color plus a written tier label; color is never the only signal.
- Locked badges show their exact criteria and progress, such as “14 of 20,” rather than mysterious requirements.
- An unlock appears after the current answer feedback, not on top of the question.
- The announcement uses a polite live region and can be dismissed with the keyboard.
- The badge cabinet offers filters for tier, topic, mission, earned, and in progress.
- The learner sees three suggested nearby badges, but can browse the full catalog at any time.

## Engineering notes

Badge definitions should be data, not conditionals scattered through UI components. Each definition contains:

```ts
type BadgeDefinition = {
  id: string;
  name: string;
  tier: "starter" | "intermediate" | "advanced";
  description: string;
  metric: string;
  target: number;
  filters?: Record<string, string | number | boolean>;
};
```

The badge evaluator must be deterministic and idempotent. Tests should verify all 100 unique IDs, tier totals of 25/50/25, boundary values immediately below and at each target, duplicate-event handling, persistence, import behavior, and reset behavior.
